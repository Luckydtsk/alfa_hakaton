# Альфа - Бузинесс — веб-клиент

React 19, TypeScript, Vite. Рабочая область изменений — только `web/`.

## Локальная разработка

```sh
npm ci
npm run dev
```

`npm ci` создаёт `node_modules` по существующему lock-файлу. `node_modules` и `dist` уже исключены из Git корневым `.gitignore`.

Vite: http://localhost:5173. Запросы `/api` проксируются на `http://127.0.0.1:3000`. Полный серверный стек запускается по инструкции в корневом README. Без API на странице входа доступен отдельный явный деморежим клиента и сотрудника. Автоматического переключения на фиктивные данные при ошибке API нет.

```sh
npm run build
node --test tests/reserve.test.mjs
```

Для запуска тестов нужен Node.js 22.18+ или 24+ с поддержкой TypeScript type stripping. Сборка приложения по-прежнему поддерживает Node.js 22 из Dockerfile.

## Структура

- `pages/` — страницы и сценарии пользователя.
- `components/` — общие элементы интерфейса, оболочка, карусель, формы профиля и договоров.
- `state/` — сессия, загрузка кабинета и состояние заявок.
- `services/gateway.ts` — интерфейс источника данных и реализация существующего API.
- `services/demoGateway.ts` — самостоятельный явно выбранный деморежим.
- `domain/` — типы и чистые функции денежных операций; форматирование заголовка и примерный расчёт.
- `hooks/` — адаптивность, защита от повторной отправки и локальная симуляция резерва.
- `services/pdf.ts` — автономная генерация учебного PDF, включая кириллицу и переносы страниц. Страницы растровые; текст PDF не является редактируемым/поисковым.

Стили элементов находятся непосредственно в JSX через `style={{ ... }}`. Общих объектов `styles` и CSS-классов оформления нет. В `styles.css` находятся только токены `:root`, сбросы и глобальные состояния элементов. Адаптивные значения вычисляются хуком `useCompact`.

## Что работает с API

Вход/выход и проверка сессии, справочники, список и создание заявок, запрос недостающих сведений, контрпредложение, решение сотрудника, подготовка документов и смоделированная выдача. ИНН и название компании берутся из серверного аккаунта. Свободный текст отправляется в существующее поле `goal`; если API не вернул `goalLabel`, интерфейс показывает исходное описание.

Авторизация и разделение доступа остаются обязанностью сервера. Ограничения маршрутов клиента предотвращают случайную навигацию между ролями и не подменяют серверную проверку.

## Границы текущего API

- Регистрации нет. Экран создания аккаунта явно создаёт только демонстрационный профиль, не хранит пароль и не выдаёт его за банковский аккаунт. Для рабочей регистрации нужен серверный маршрут с пользователем, компанией, профилем, проверкой уникальности и серверной сессией.
- Расширенного профиля нет. Возраст, отрасль и сотрудники берутся из последней заявки или локального профиля конкретного аккаунта. Недостающие сведения запрашиваются один раз через профиль и передаются при создании заявки. ИНН и название существующего аккаунта на фронтенде не подменяются.
- Овердрафта и счёта нет. Резерв — изолированная локальная симуляция, помеченная на каждом экране. Для интеграции нужны договор/лимит, состояние задолженности и собственных средств, операции платежа/поступления, история, правила процентов/погашения и серверная идемпотентность.
- Ставки, комиссии, готовые договоры и графики не возвращаются API. Калькулятор 18% — явно обозначенный учебный пример; PDF — учебный образец из фактических параметров заявки, без выдуманных банковских ставок.

В деморежиме профиль и заявки хранятся в браузере; пароль не сохраняется. Реальная сессия использует cookie API с `HttpOnly`. Данные профиля и симуляции резерва разделены по режиму и идентификатору пользователя.

`design/prototype.html` сохранён как исходный согласованный HTML-референс, а не как встроенная в React страница.
